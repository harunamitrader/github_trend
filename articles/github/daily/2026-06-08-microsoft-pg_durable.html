これは何か

pg_durable は、PostgreSQL extension として動く durable execution の実装です。ワークフローを SQL で定義し、各ステップをチェックポイントしながら、失敗や再起動のあとでも処理を続けられるようにします。

何ができるか

長時間走る SQL 関数や背景処理を、外部キューや別のワーカー基盤に頼らずに Postgres の内部で扱えます。crash、restart、failed step のあとに復帰しやすく、バックグラウンドジョブの運用を単純化できます。

目立つポイント

README が強調しているのは、Zero infrastructure で動くことと、PostgreSQL 17 / 18 を前提にした配布です。タグ付きリリースでは Debian パッケージも公開され、extension library、control file、SQL upgrade files をまとめて導入できます。

セットアップや使い方の流れ

まずリリースパッケージを入れたうえで、`shared_preload_libraries` に `pg_durable` を追加し、PostgreSQL を再起動して extension を作成します。ローカル検証では `pg-start.sh` や `~/.pgrx` ベースの手順も使えます。

どんな人向けか

Postgres を基盤にしていて、cron・queue・worker をまとめて整理したいチームに向いています。バックエンドの状態管理を SQL 側へ寄せたい場合にも相性がいいです。

注意点

PostgreSQL extension と background worker の設定に慣れていないと、初期導入で止まりやすいです。運用前に権限、再起動、接続先データベースの前提を確認しておくほうが安全です。

まとめ

pg_durable は、Postgres をそのまま durable execution の実行面にしたいときの有力候補です。既存のデータ基盤を大きく変えずに、長時間処理の復帰性を上げたい場合に価値があります。
