これは何か

Dicklesworthstone/destructive_command_guard (dcg) は、自律型 AI エージェント（Claude Code や Cursor, Cline など）による、危険なシェルコマンドや破壊的な git コマンドの誤実行を未然に防止するための、オープンソースのセキュリティゲートウェイシステムです。プロキシのようにシェルとエージェントの間に介在し、コマンドの安全性を自律評価・ブロックします。

何ができるか

エージェントが生成したコマンドラインを監視し、`rm -rf /` のような OS レベルの破壊コマンドだけでなく、`git reset --hard` や `git push --force` といったローカル環境やチームのソースツリーを破壊する恐れのある git コマンドをパターンおよびセマンティクス解析で遮断できます。ブロックされたコマンドは実行前に人間に確認を求め、許可された場合のみ実行します。

目立つポイント

AI の「自律実行（Auto-mode）時の暴走リスク」をスマートに防ぐ点が最大の特徴です。エージェントが良かれと思って「競合を解決するために古いブランチ履歴を強制リセットで消去する」といった重大な事故が相次ぐ中、ユーザーが事前に指定した拒否リスト（Deny-list）や機微なコマンドルールに基づいて確実に防波堤として機能します。

セットアップや使い方の流れ

Python 3 環境でリポジトリからスクリプトを導入し、エージェントがコマンドを実行する際の実行パス（エイリアス）として dcg プロキシを挟み込みます。拒否したいコマンドラインパターンや警告を発するルールを YAML 等で構成しておくことで、エージェントがコマンドを発行した瞬間に割り込んで安全性を評価し、警告アラートを出力させます。

どんな人向けか

自律モードをオンにして AI エージェントを放置開発（オーバーナイトラン等）させる機会が多いエンジニア、または企業の開発インフラに AI エージェントを導入する際のセキュリティリスクや操作ミスによるデータ損失を懸念する情報システム管理者に最適です。

注意点

過剰に検知ルールを設定しすぎると、エージェントの実行速度（開発効率）が極端に損なわれたり、正当な git 操作であっても何度もブロックされ人間の手動承認を求められるという煩わしさが生じる可能性があります。プロジェクトの機微度合いに応じたルールセットのチューニングが必要です。

まとめ

AIエージェントの有能さと暴走リスクのトレードオフを解消し、自律実行モードの安全性を劇的に高める、これからのエージェント協調開発時代に必須となる実用性の高いセキュリティ・ガードレールです。
