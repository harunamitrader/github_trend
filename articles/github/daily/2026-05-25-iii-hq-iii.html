これは何か

iii は、stack 内のサービスをリアルタイムで compose・extend・observe するための基盤です。worker を登録し、trigger と function を同じ見取り図で扱うことで、分散した実行環境を 1 つの live catalog にまとめます。

何ができるか

iii worker add queue のように機能を追加すると、他の worker からすぐ呼び出せる状態になります。queue、cron、HTTP、state、agents、sandbox をひとつの interface で扱えるので、開発だけでなく運用や観測も同じ流れで回せます。

目立つポイント

iii の核は Worker / Function / Trigger の 3 つだけです。構成要素が少ないぶん、何がどこで動いていて、どこから呼ばれているかを追いやすく、workers.iii.dev の catalog と実行トレースを前提にした設計が分かりやすいです。

セットアップや使い方の流れ

まず iii project init myapp でプロジェクトを作り、iii を起動してエンジンを立ち上げます。その後は worker を足し、function を登録し、必要な trigger を宣言していく流れです。README の quick start と SDK 一覧も、その導線に沿って整理されています。

どんな人向けか

サービスを増やすたびに個別の接続や監視設定を増やしたくないチーム向けです。AI agent を含む複数の実行主体を、同じ catalog と trace で見たい場合にも相性がいいです。

注意点

自由度が高いぶん、最初から何でも自動化するより、まず worker 単位で責務を分ける方が運用しやすいです。エンジン、SDK、console の役割を分けて把握しないと、機能が多いだけの基盤になりやすい点には注意が必要です。

まとめ

iii は、service composition と observability を同じ操作面に乗せるための基盤です。AI や自動化を含むシステムを増やしていくほど、worker 中心の設計の価値が出やすい repo です。
