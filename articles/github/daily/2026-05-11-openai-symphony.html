これは何か

Symphony は、OpenAI が開発した、AI エージェントの実行を自律化・効率化するための オーケストレーション・フレームワーク です。人間が逐一指示を出すのではなく、Linear などのプロジェクト管理ツール上の「タスク（チケット）」をトリガーにして、エージェントが自律的に作業を開始・完了するためのエコシステムを提供します。

何ができるか

Linear のボードを監視し、特定のステータスになったタスクを自動でピックアップします。その後、タスクごとに独立した隔離環境（Docker 等）を構築し、Codex などのエージェントを起動してコード作成、テスト実行、プルリクエストの作成までを自動で行わせます。作業完了時には、実行ログや分析結果、さらには作業内容を解説する「ウォークスルー動画」まで生成し、人間にフィードバックします。

目立つポイント

最大の特徴は、エージェントが自ら仕事を取りに行く 「プル型」のワークフロー を実現している点です。また、「Harness Engineering（ハーネス・エンジニアリング）」 という思想を掲げており、エージェントが確実に成果を出せるように「テスト、CI、環境、ツール」といった周辺インフラを整えることを重視しています。設定はリポジトリ内の WORKFLOW.md で管理でき、プロジェクトごとにエージェントの挙動を詳細に定義可能です。

セットアップや使い方の流れ

利用には Linear の API キー、OpenAI の API キー、Docker、およびツール管理用の mise が必要です。リポジトリ内に WORKFLOW.md を配置し、Elixir 製の Symphony サービスを起動して Linear ボードの監視を開始します。あとは Linear 上でタスクを作成し、ステータスを専用のもの（例: Symphony: Active）に変更するだけで自動化が始まります。

どんな人向けか

AI エージェントを単なる「チャットボット」ではなく、開発チームの「自律的な一員（同僚）」として本格的に統合したい先進的な開発チームや、大量の定型タスク・メンテナンス業務を自動化したいプロダクトマネージャーに最適です。

注意点

現時点では「Developer Preview」であり、実験的な性質が強いプロジェクトです。リファレンス実装は Linear との連携を前提としており、GitHub Issues などの他のツールで利用するには独自のカスタマイズが必要になります。また、GUI はなく、操作は基本的に既存のタスク管理ツール上で行います。

まとめ

Symphony は、人間が「何をすべきか（WHAT）」をチケットに書き、AI が「どのように実現するか（HOW）」を担うという、次世代のソフトウェア開発スタイルのプロトタイプです。AI エージェントと人間の協調を「オーケストレーション」という一段高い視点から再定義する、非常に野心的なプロジェクトと言えるでしょう。
