これは何か

AX は、エージェントの実行ループを分散環境で扱うためのランタイムです。controller が実行を調停し、skills、tools、agents を分離して扱えるので、単体のエージェントフレームワークよりも「運用層」に近い作りになっています。

何ができるか

イベントログを残しながら agentic loop を回し、途中で止まっても復帰できるように設計されています。ローカル実行とリモート実行の両方を扱え、会話の継続、fork、trace、serve といった操作を通じて、長時間タスクの管理をまとめて行えます。

  • 分散実行: controller、agent、tool を分離して実行できます。
  • 復帰機能: conversation と sequence を使って中断後に再開できます。
  • 監査性: すべての呼び出しを event log で追跡できます。

目立つポイント

この repo の中心は、エージェントを「長く走る分散ワーカー」として扱う前提です。単発の CLI ツールではなく、Kubernetes も視野に入れた実行基盤として作られているため、失敗時の復帰や状態管理を初めから重視しています。

  • resumption first: 中断や切断を前提にした設計です。
  • single-writer: 状態管理の一貫性を取りやすい構成です。
  • framework agnostic: 特定のエージェント実装に固定されません。

セットアップや使い方の流れ

まず `go install github.com/google/ax/cmd/ax@latest` で CLI を入れます。そこから `ax exec` で実行を開始し、必要に応じて `ax serve` で controller を立て、`ax trace` で実行の流れを確認する運用になります。

どんな人向けか

長時間動く agent system を組みたい人、復帰や監査を最初から考慮した基盤が欲しい人、個別の agent 実装ではなく実行レイヤーを整えたい人に向いています。特に、複数 agent や remote agent をまたいで仕事をさせたい場面に合っています。

注意点

README にもある通り、AX はまだ early active development です。実装や resumption protocol は今後変わる前提なので、本番導入では API 変更と設計変更の追従を見込む必要があります。

まとめ

AX は、エージェントを個別ツールではなく「分散して復帰可能な実行系」として扱うための基盤です。長時間タスクや監査要件がある agentic system を作るときに、土台として見ておきたい repo です。
