これは何か

SkillOpt は、モデル重みをいじらずに、エージェントに持たせる自然言語スキル自体を最適化するための基盤です。 公式 README では、trajectory-driven edits と validation-gated updates を通じて、再利用可能な skill を磨き込み、最終的に deployable な best_skill.md を出力する設計になっています。 要するに、「プロンプトを毎回手で直す」のではなく、「改善されたスキルを成果物として配る」方向に寄せた repo です。

何ができるか

  • スキルを反復改善: 失敗した trajectory を使って、自然言語の指示や手順を更新できる。
  • 検証で足切り: validation gate を通らない変更は採用しない運用にできる。
  • 配布しやすい成果物: 最終的な skill を best_skill.md として持ち出せる。
  • 複数ベンチに対応: SearchQA、ALFWorld、DocVQA、SpreadsheetBench、OfficeQA などの split ベースのデータで評価しやすい。

目立つポイント

この repo のユニークさは、学習の単位を「モデル」ではなく「スキル文書」に置いている点です。 epochs、mini-batchsize、learning rate のような発想を、LLM の重み更新ではなく、スキル改善の反復にそのまま持ち込んでいます。 frozen LLM を前提にしているので、モデル再学習よりも軽く、運用しやすい改善ループを作りやすいのが強みです。

セットアップや使い方の流れ

  1. リポジトリを clone して pip install -e . で開発環境を入れる。
  2. API 認証情報を設定 する。README では Azure OpenAI、OpenAI、Anthropic Claude、Qwen などを想定している。
  3. データを split 形式で準備 する。train / val / test に分けた JSON を置く。
  4. 学習を実行 する。たとえば python scripts/train.py --config ... --split_dir ... の形で回す。

どんな人向けか

  • 固定済み LLM を前提に、プロンプトや skill を継続改善したい人。
  • エージェントの振る舞いを、検証付きのワークフローとして管理したいチーム。
  • 研究用の試行錯誤を、配布可能な best_skill.md に落とし込みたい開発者。

注意点

  • Python 3.10+ が必要: README 上の前提環境を満たしていないと動かしにくい。
  • データは自前で用意する: benchmark データセットは同梱されていないため、split 形式で準備する必要がある。
  • API キー前提: Azure OpenAI などの LLM 接続先を設定しないと、学習ループが回らない。

まとめ

SkillOpt は、LLM の中身を再学習するのではなく、エージェントに与えるスキルを訓練・検証・配布するための実装です。 自動化したいのは「モデル重み」ではなく「運用できる skill の質」だ、というチームにはかなり相性がよいです。
