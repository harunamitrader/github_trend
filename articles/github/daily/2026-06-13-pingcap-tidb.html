これは何か

TiDB は、増え続けるデータや負荷に対応しやすい分散 SQL データベースです。ACID を保ちながら、トランザクション処理と分析系の負荷を同じ基盤で扱いやすいのが強みです。

何ができるか

業務アプリの基盤として、通常の CRUD だけでなく、集計や分析、ベクトル検索のような処理も視野に入れやすくします。データを分断せずに持ちたい場面で役立ちます。

目立つポイント

MySQL 系の接続イメージを保ちつつ、スケールアウト前提の設計を取りやすい点が目立ちます。データ量や同時アクセスが読みにくい環境でも、伸びしろを確保しやすい構成です。

セットアップや使い方の流れ

まず利用形態を TiDB Cloud か自己運用かで決め、クラスタを用意します。その後、アプリから接続してスキーマやインデックスを整え、バックアップと監視を運用に組み込みます。

どんな人向けか

利用者数やデータ量の増加に備えたい開発チーム、分析基盤と業務 DB を寄せたいチーム、AI 周辺の検索基盤を整えたい人に向いています。

注意点

分散 DB なので、単純な単一ノード DB と同じ感覚では運用できません。スキーマ設計、バックアップ、障害対応の手順を最初から固めておく必要があります。

まとめ

成長余地のある業務データを一つの基盤で扱いたいときに、分散 SQL の選択肢として有力です。
