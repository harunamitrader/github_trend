これは何か

MemMachine は、AI agents と LLM-powered applications 向けの long-term memory layer です。会話やイベントの履歴をただ保存するのではなく、エージェントが学習し直せる形で記憶を残し、状態を持つアシスタントへ寄せる設計になっています。

何ができるか

README では、Episodic Memory、Profile Memory、Working Memory の 3 層が説明されています。会話文脈を graph ベースで持ち、ユーザーの好みや属性は SQL に分けて保存できるので、検索と再利用を両立しやすい構成です。

目立つポイント

LangChain、LangGraph、CrewAI、LlamaIndex、AWS Strands などのフレームワークに加えて、n8n、Dify、FastGPT ともつながるのが強みです。さらに MCP server を用意しているので、Claude Desktop や Cursor などの MCP 対応クライアントにも載せやすいです。

セットアップや使い方の流れ

README の導入例では、まず `pip install memmachine-client` を入れ、`MemMachineClient(base_url="http://localhost:8080")` で接続します。次に project を作成し、memory instance を用意してから `add` や `search` を呼ぶ流れです。サーバーはローカル起動か、管理サービスを使う前提になっています。

どんな人向けか

チャットの履歴を積むだけでなく、ユーザーごとの記憶や文脈を再利用したい人向けです。エージェントの state management をアプリ側から切り離して整理したい場合にも使いやすいです。

注意点

メモリ基盤は入れるだけでは効かず、何を episodic にし、何を profile に分けるかの設計が重要です。導入前に保存ポリシーと検索条件を決めておかないと、記憶が増えるほどノイズも増えます。

まとめ

MemMachine は、AI エージェントに持続的な記憶を与えるための実装寄りの基盤です。単なるベクトル検索ではなく、状態を分けて運ぶメモリ層が欲しいなら候補になります。
