GitHub Watcher

checkout

GitHub Actions のワークフロー内でリポジトリのコードをクローンし、安全にチェックアウトするための公式アクション

記事作成日 2026-07-04
種別 GitHub Trending 5位
対象 repo actions/checkout
Star数 8,250

これは何か

GitHub Actions のワークフロー内で実行される最も基本的な公式アクションの一つです。CI/CDジョブを実行する仮想環境（ランナー）に対し、対象のGitHubリポジトリからコードを取得（git clone / fetch）してチェックアウトする機能を提供します。

何ができるか

特定のコミットハッシュやブランチ、PR（Pull Request）のコードのチェックアウト、コミット履歴の取得数（fetch-depth）の制御、サブモジュールの再帰的取得、Git の認証情報の永続化（persist-credentials）などを簡単な宣言で実行できます。

目立つポイント

最新のメジャーバージョンである v7 では、pull_request_target や workflow_run などのトリガーで実行される際、フォークされたリポジトリからのPRコードの自動的なチェックアウトをデフォルトで拒否する「セーフティシャッター」が導入され、ランナー乗っ取り脆弱性（pwn request）への安全性が劇的に向上しました。

セットアップや使い方の流れ

GitHub Actions のワークフロー定義ファイル（YAML）の steps セクションにおいて、- uses: actions/checkout@v7 を記述するだけで導入できます。必要に応じて、with パラメータで履歴取得数（fetch-depth: 0）などを調整します。

どんな人向けか

GitHub Actions を使ってビルド、テスト、静的解析、デプロイなどのCI/CDパイプラインを構築・運用しているすべてのエンジニアおよび開発チーム向けです。

注意点

デフォルトでは、トリガーとなった特定の1コミットのみを取得（シャロークローン）するため、Gitの全コミット履歴を必要とする差分ビルドやツール（一部の静的解析ツールなど）を実行する際には fetch-depth: 0 の明示的指定が必要です。

まとめ

GitHub Actions の要となるインフラ的コンポーネントであり、今回の v7 リリースによる認証とセキュリティ保護の強化は、オープンソースのサプライチェーン攻撃対策において重要なマイルストーンです。
