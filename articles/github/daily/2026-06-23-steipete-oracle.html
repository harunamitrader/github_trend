これは何か

oracle は、質問文と対象ファイルをまとめて 1 つのコンテキストに束ね、CLI からそのまま LLM に渡せる開発者向けツールです。API 経由の実行だけでなく、サインイン済みブラウザを使ったブラウザモードも持ち、コード付きで AI に相談するまでの手間を大きく減らします。

何ができるか

GPT-5.5 Pro、Gemini 3.1 Pro、Claude Sonnet 4.6 など複数モデルを 1 回の実行で呼び分けたり、同時比較したりできます。API キーを使う通常モードに加え、ChatGPT や Gemini にログイン済みの Chrome を自動操作するブラウザモード、`--copy` による手動貼り付け、過去セッションの再実行、ChatGPT Project Sources へのファイル追加までカバーしています。

目立つポイント

最大の特徴は、単なる CLI ラッパーではなく `oracle-mcp` として MCP サーバーにもなれる点です。Codex や Cursor、Claude Code など別の開発環境からも同じ文脈投入フローを再利用でき、ブラウザモードでは API キーなしで ChatGPT Pro 系の Web UI を使う経路まで用意されています。

セットアップや使い方の流れ

利用には Node 24 以上が必要で、`npm install -g @steipete/oracle` か `npx -y @steipete/oracle` で起動できます。API モードでは `OPENAI_API_KEY` などを設定し、ブラウザモードでは初回に `oracle --engine browser --browser-manual-login -p "HI"` を実行して専用プロファイルからログインします。その後は `-p` で指示文、`--file` で対象ファイル群を指定すれば動きます。

どんな人向けか

局所的なコードレビューやデバッグを素早く回したい開発者、同じ入力を複数モデルに投げて差分を見たいエンジニア、既存の AI エディタ環境へ MCP 経由で追加の相談先を差し込みたいパワーユーザーに向いています。

注意点

ブラウザ自動化は便利ですが実験的機能で、README でも API モードのほうがより安定すると明記されています。Windows や Linux では Cookie 取得や Chrome 検出まわりの調整が必要になる場合があり、当然ながらローカルファイルを外部モデルへ送る以上、機密コードを扱う際は送信先と運用ポリシーの確認が前提です。

まとめ

oracle は、プロンプトとファイルをまとめて AI に渡す作業を CLI、MCP、ブラウザ自動化の 3 経路で統一する実務寄りの道具です。単発の相談からエージェント連携まで守備範囲が広く、AI 開発フローの配線役として見ても面白いリポジトリです。
