これは何か

Hiring Agent は、求職者の履歴書（PDF）を解析し、LLM（大規模言語モデル）を用いて JSON 形式で構造化した後、GitHub アカウントからオープンソースへの貢献実績やリポジトリの評価（Star数等）などのシグナルを取得して統合し、公平で説明可能な採用評価スコアを自動生成する Resume-to-Score パイプラインエージェントです。

何ができるか

PyMuPDF を用いて履歴書 PDF を Markdown に変換し、Jinja テンプレートに基づき各項目（学歴、職歴、スキル、プロジェクト等）を LLM で抽出します。抽出されたプロフィールから GitHub ユーザー名を割り出し、リポジトリ群のコミットしきい値やスター数を分析して上位 7 プロジェクトを LLM に選定させます。最後に、定義された公平性ルールとスコアリング規則に基づき、オープンソース活動、技術スキル、プロダクション経験などを厳格にスコア化して CSV に出力します。

目立つポイント

Ollama を用いた完全ローカル環境（Gemma 3 等）と Google Gemini API（Gemini 2.5 Pro 等）の両方をバックエンドとして切り替えて使用できる点、AI の恣意的な判定を防ぐために Jinja テンプレート内に厳格な公平性制約（fairness constraints）をエンコードしている点が非常に実用的です。

セットアップや使い方の流れ

リポジトリをクローン後、依存パッケージをインストールし、.env ファイルに LLM プロバイダ（ollama または gemini）、モデル名、API キーなどを設定して、python score.py を実行します。

どんな人向けか

求職者の応募書類の選考プロセスを半自動化し、主観ではなくコードへの実際の寄与度（GitHub等）に基づいた客観的かつ公平な一次選考スクリーニングを行いたい採用チームや人事担当者、LLM を実務プロセスに組み込むワークフロー開発者に最適です。

注意点

PDF のレイアウトや記述内容によっては、LLM が GitHub ユーザー名を正しく抽出できない場合があります。また、採用に関わる判定を自動で行うため、最終的な判定には人間のレビューを挟むことが必須です。

まとめ

Hiring Agent は、書類上の経歴だけでなく、GitHub などの客観的な開発シグナルを自動でクロスマッチさせて評価することで、技術スキルの信頼性の高い採用一次評価を可能にする、LLM 時代の極めて実用的な自動採用支援エージェントツールです。
