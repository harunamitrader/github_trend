これは何か

Mirage は、AI エージェントが扱う複数の外部サービスを、1 つの仮想ファイルシステムとして見せる基盤です。 RAM、S3、Slack、Gmail、Google Drive、GitHub などを同じツリーに並べ、bash に近い操作感で扱えるようにします。

何ができるか

エージェントは `ls`、`cat`、`grep`、`cp` のような Unix 風コマンドを使って、サービスをまたいで読み書きできます。 Python と TypeScript の SDK もあり、FastAPI や Express、各種エージェントフレームワークに組み込みやすい構成です。

さらに、コマンドを拡張したり、ファイル種別ごとに挙動を差し替えたりできるため、単なる接続集ではなく 「AI が理解しやすい作業環境」を作れるのが強みです。

目立つポイント

強いのは、サービスごとに個別 API を覚えさせるのではなく、ファイルシステムという共通言語に寄せている点です。 これで LLM が慣れている bash の文法をそのまま使いやすくなり、マウント先が増えても操作モデルが増えにくくなります。

セットアップや使い方の流れ

Python なら `uv add mirage-ai`、TypeScript なら用途に応じて `@struktoai/mirage-node` や `@struktoai/mirage-browser` を入れます。CLI はインストールスクリプトや `npm`、`uvx` から起動でき、 まずは Workspace を作ってリソースを mount し、`execute()` でコマンドを投げる流れです。

どんな人向けか

SaaS を横断する AI ワークフローを作りたい人、エージェントに「1 つの作業台」を渡したい人、 複数のバックエンドを同じ操作感で扱いたいチームに向いています。

注意点

README では macOS / Linux 前提の FUSE 利用や、Python 3.12、Node.js 20 以上などの条件が案内されています。 連携先ごとの認証や権限設定も必要なので、導入前に対象サービスの前提条件を揃えておくのが安全です。

まとめ

Mirage は、AI エージェント向けに外部サービスを 1 つの仮想ファイルシステムへまとめる実用的な基盤です。 API を増やすよりも、LLM に馴染みのあるファイル操作へ寄せたい場面でかなり相性が良いです。
