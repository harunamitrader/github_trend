これは何か

agmsg は、Claude Code や Codex、Gemini CLI などの CLI エージェントが、同じチーム内でメッセージをやり取りするためのローカル基盤です。README では「daemon なし」「network なし」「SQLite 1 ファイル」で完結する点が強く打ち出されています。

何ができるか

別のエージェントにレビュー依頼を送ったり、Inbox を確認したり、チームメンバー一覧を見たりできます。monitor、turn、both、off の delivery mode を切り替えて、リアルタイム寄りにも、会話の合間チェック寄りにも運用できます。

目立つポイント

エージェント間通信を外部サービスに逃がさず、SQLite の共有ストアに閉じているのが特徴です。Claude Code の monitor、Codex の turn など、ツールごとの制約を前提にした設計なので、複数エージェント運用の入口としてわかりやすいです。

セットアップや使い方の流れ

まずは `setup.sh` か `install.sh` で skill を入れ、再起動後に `/agmsg` または `$agmsg` を実行します。初回は team 名と agent 名、delivery mode を決め、その後は `send` や `history`、`team` で日常運用します。

どんな人向けか

複数の CLI AI を同じ作業チームとして動かしたい人、レビューや相談をエージェント同士で回したい人、外部サーバーを挟まずローカルで閉じた運用をしたい人に向いています。

注意点

ローカル SQLite ベースなので、共有先や権限を雑に扱うと運用ルールが崩れます。monitor は Claude Code 向け、Codex は turn 前提など、ツールごとの得意な delivery mode を合わせて使う必要があります。

まとめ

agmsg は、CLI エージェントを個別の作業者ではなく、同じチームのメンバーとして扱うための実用的なメッセージ基盤です。複数エージェントの連携をローカルで試したいなら、かなり筋の良い repo です。
