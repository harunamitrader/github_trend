これは何か

WeKnora は、公開 README で「Open-source LLM knowledge platform」と説明されている知識基盤です。 生の文書を、そのまま問い合わせ可能な RAG、複雑な手順を進める ReAct Agent、そして維持しやすい Wiki に 変換することを狙っています。

何ができるか

ふだんの問い合わせには RAG ベースの Quick Q&A を使い、複数ステップの処理では Agent が検索・ツール利用・ Web 検索をまとめて回します。さらに Wiki Mode では、元文書から相互リンク付きの Markdown Wiki を 自動生成し、ナレッジを保守しやすい形に整えます。

取り込み元は Feishu、Notion、Yuque などで、今後のソース追加も案内されています。文書形式も PDF、Word、 画像、Excel、PPT、JSON まで幅広く、問い合わせチャネルは WeCom、Feishu、Slack、Telegram などに広がっています。

目立つポイント

目立つのは、単なる検索エンジンではなく「知識を作り直す」方向に寄っている点です。単発の Q&A だけでなく、 Wiki 化と長期保守を含めて設計されているため、社内ナレッジの再利用性が高い構成になっています。

もう一つの強みは、20 以上の LLM プロバイダー対応と Langfuse による可観測性です。モデル選択と追跡が見えるので、 企業利用で気になりやすい監査性と運用性を両立しやすくしています。

セットアップや使い方の流れ

README では、まず Docker Compose で core services を起動し、その後に Web UI へアクセスする流れが案内されています。 開発時は `just setup` で環境を整え、`just dev` で backend と frontend を分けて立ち上げる形です。

さらに、`weknora` という CLI が用意されており、知識ベースのリンク、アップロード、チャットなどをターミナルから 操作できます。MCP サーバーも備わっているので、Claude Code などの AI エージェントからの呼び出しにもつなげやすいです。

どんな人向けか

社内文書を RAG で検索したいチーム、問い合わせ対応を半自動化したい運用担当、Wiki と QA を一体で整えたい ナレッジ管理チームに向いています。特に、データを外部 SaaS に閉じ込めずに自前で運用したいケースと相性が良いです。

注意点

README には、v0.1.3 以降でログイン認証が入ること、公開ネットワークに直接さらすより内部・プライベート環境で 運用することが推奨されていることが書かれています。RBAC、ソース接続、モデル設定まで含めると、 立ち上げ時の設計はやや重めです。

まとめ

WeKnora は、文書検索を超えて、RAG、Agent、Wiki をひとつの知識運用基盤にまとめたプロジェクトです。 企業内の散在した情報を実用的なナレッジ資産に変えたい場面で、かなり筋の良い選択肢です。
