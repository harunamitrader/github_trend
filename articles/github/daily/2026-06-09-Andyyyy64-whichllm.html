これは何か

whichllm は、GPU / CPU / RAM を自動判定して、その環境で実際に走るローカル LLM の候補を並べる CLI です。Hugging Face のモデル情報とベンチマークを組み合わせて、「入るか」ではなく「何を動かすべきか」を決めやすくします。

何ができるか

`whichllm` をそのまま実行すると、現在のマシンに合う候補が順位付きで出ます。`--gpu` で RTX 4090 のような仮想構成を試したり、`plan` で必要な GPU を逆算したり、`run` や `snippet` でそのまま起動やコード出力につなげたりできます。`--json` もあるので、スクリプトからの利用にも向いています。

目立つポイント

README では、LiveBench や Aider、Chatbot Arena、Open LLM Leaderboard などの評価をまとめ、古いスコアをそのまま信用しない設計が強調されています。モデルのサイズだけで決めず、更新時期や証拠の強さまで見て順位を調整するので、単純な「大きい方が上」になりにくいです。

セットアップや使い方の流れ

まずは `uvx whichllm@latest` で試し、頻繁に使うなら `uv tool install whichllm` に切り替えるのが素直です。次に `whichllm --gpu "RTX 4090"` で手元の想定環境を確認し、結果を見ながら `whichllm run` や `whichllm --top 1 --json` に進むと、選定から実行までがつながります。

どんな人向けか

ローカル LLM を本気で使いたい人、GPU を買う前に候補を見たい人、Ollama や llama.cpp につなぐ前の比較を自動化したい人に向いています。開発用の補助ツールというより、モデル選定の判断エンジンとして使う方が分かりやすいです。

注意点

結果は Hugging Face のライブデータとキャッシュに依存するので、同じ日でも候補や順位は変わります。Apple Silicon と CPU only は GGUF 前提になりやすく、速度も実測値ではなく推定なので、最終判断は自分のバックエンドとベンチで確認したほうが安全です。

まとめ

whichllm は、ローカル LLM を「動くか」だけでなく「どれを動かすべきか」まで一気に判断しやすい CLI です。モデル選定の手戻りを減らしたいなら、かなり実用的な入り口になります。
