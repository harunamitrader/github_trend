これは何か

agent-desktop は、AI エージェント向けに作られたデスクトップ自動化 CLI です。画面を画像で見て操作するのではなく、macOS のアクセシビリティ情報を使ってアプリの構造を読み取り、ボタンや入力欄を安定して扱えるようにしています。

何ができるか

アプリの一覧やウィンドウ、要素ツリーを取得し、`click`、`type`、`press`、`scroll` などの操作を構造化 JSON で実行できます。`snapshot` と `@e1` のような deterministic な参照を使えるので、複雑な画面でも対象要素を追いやすいです。

  • アクセシビリティベースの操作: スクリーンショット依存を避け、構造を優先して操作します。
  • 順序立てた観測: snapshot と ref を使って、観察→判断→実行のループを回せます。
  • FFI 対応: CLI だけでなく C-ABI cdylib でも呼び出せます。

目立つポイント

この repo の強みは、AI が画面を「見る」のではなく、OS が持つ構造情報をそのまま利用する点です。Token 消費を抑えやすく、要素参照も安定しやすいため、Slack や Finder のような密な UI でも扱いやすい設計になっています。

  • Structured JSON output: エラーコードや復帰ヒントまで機械的に返します。
  • Headless-by-default: 余計な副作用を抑えた操作設計です。
  • Permissions 管理: Accessibility や Screen Recording の許可状態を明示的に確認できます。

セットアップや使い方の流れ

まず `npm install -g agent-desktop` で導入し、macOS のアクセシビリティ権限を付与します。実行後は `snapshot --app ` で UI 構造を確認し、`click` や `type` を ref 指定で呼び出していく流れです。必要に応じて `npx agent-desktop ...` でも試せます。

どんな人向けか

ブラウザではなくローカルアプリを AI に操作させたい人、スクリーンショット中心の自動化で不安定さを感じている人、CLI とアプリ操作をひとつのワークフローにしたい人に向いています。特に macOS の GUI 操作を安全寄りに扱いたいケースと相性が良いです。

注意点

macOS 前提で、Accessibility と Screen Recording の権限が必要です。使える操作は OS のアクセシビリティツリーに依存するため、アプリ側が適切な情報を公開していないと十分に扱えない場合があります。

まとめ

agent-desktop は、AI エージェントにデスクトップの「構造」を渡すための実用的な CLI です。画像認識ベースよりも安定した GUI 操作を求める場面で、かなり相性のよい repo です。
